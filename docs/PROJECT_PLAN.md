## 二、專題概述 Planning

### 1.1 動機與背景

在宿舍生活中，洗衣服是住宿生經常會遇到的日常需求，但實際使用洗衣機時常常會發生不方便的情況。例如學生抱著衣服到洗衣間後，才發現洗衣機全部都在使用中，或是某台機器已經故障卻沒有明確標示，造成時間與體力的浪費。

因此，我們希望設計一套「LaundryNow：宿舍洗衣機即時狀態查詢系統」，讓住宿生可以先在線上查看洗衣機目前是否空閒、使用中或故障，也能回報剩餘時間與機器狀態，提升宿舍洗衣的便利性與效率。

### 1.2 目標使用者

這個系統主要設計給住宿學生使用，特別是需要共用宿舍洗衣機的學生。

他們的特性與需求包括：

住宿生經常需要使用公共洗衣機，但不一定知道目前哪一台洗衣機可以使用。使用者希望在洗衣前先查詢洗衣機狀態，避免抱著衣服白跑一趟，也希望能知道機器是否故障、使用中或大約還需要等待多久。

### 1.3 專題目標

| 目標編號 | 專題目標 |
|---|---|
| 目標一 | 讓住宿生可以查看宿舍洗衣機目前的使用狀態。 |
| 目標二 | 讓使用者可以回報洗衣機是空閒、使用中或故障。 |
| 目標三 | 讓使用者可以輸入洗衣機剩餘使用時間，方便其他人判斷等待時間。 |
| 目標四 | 減少學生到洗衣間後才發現沒有機器可用的情況。 |
| 目標五 | 建立簡單清楚的操作介面，讓使用者能快速查詢與回報。 |

## 三、需求分析 Requirements Analysis

### 2.1 功能性需求 Functional Requirements

| 功能編號 | 功能名稱 | 功能描述 |
|---|---|---|
| F-01 | 查看洗衣機狀態 | 使用者可以查看所有洗衣機目前狀態，例如空閒、使用中或故障。 |
| F-02 | 回報洗衣機狀態 | 使用者可以選擇洗衣機編號，並更新該洗衣機目前狀態。 |
| F-03 | 設定剩餘時間 | 當洗衣機正在使用中時，使用者可以輸入預估剩餘使用時間。 |
| F-04 | 新增洗衣機資料 | 使用者可以新增洗衣機編號、所在樓層或地點。 |
| F-05 | 編輯與刪除資料 | 使用者可以修改錯誤資料，或刪除不需要的洗衣機紀錄。 |

### 2.2 非功能性需求 Non-functional Requirements

| 類別 | 需求描述 |
|---|---|
| 效能 | 系統操作需快速，使用者更新洗衣機狀態後，頁面能顯示最新資訊。 |
| 安全性 | 系統需避免空白輸入或錯誤格式，例如剩餘時間不可輸入負數。 |
| 易用性 | 介面要簡單清楚，使用顏色或文字標籤區分空閒、使用中與故障狀態。 |
| 可維護性 | 程式碼依功能區分，方便後續新增更多洗衣機或宿舍地點。 |

### 2.3 範圍限制 Out of Scope

本次不包含：

- 使用者登入、註冊與個人帳號系統。
- 真正連接洗衣機硬體感測器，只由使用者手動回報狀態。
- 手機 App 版本，只製作網頁版系統。
- 線上付款、洗衣預約或自動通知功能。

| 風險 | 發生可能性 | 影響程度 | 因應策略 |

## 八、結論

本報告依照課堂 SDLC 開發流程範本製作。LaundryNow 的目標是解決住宿生洗衣前無法即時知道洗衣機狀態的問題，透過 Flask、SQLite 與簡潔的網頁介面，建立一套可查詢、可回報、可維護的宿舍洗衣機即時狀態查詢系統。
